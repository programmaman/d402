# d402 0.5.0 — Signed Transactions, Centralized Retry, and Native Facilitation

This is the implementation specification for d402 `0.5.0`.

The implementation is performed sequentially by agents in the same working tree on the `release/0.5.0` branch. Agents must not create worktrees, reset unrelated work, or modify files outside their assigned task. After each task, the main agent reviews the changes and runs the task's validation before crossing out the task.

The dPayments SDK and deployed contracts remain unchanged.

## Final architecture

```text
dPayments SDK
  ↓
PreparedTx
  ↓
D402Signer.signTx()
  ↓
SignedTx
  ↓
D402TxBroadcaster.broadcastTx()
  ↓
D402BroadcastResult
```

Responsibilities:

```text
D402Signer
  obtains the wallet address
  populates nonce and gas
  signs PreparedTx

D402TxBroadcaster
  submits SignedTx
  translates provider results into D402BroadcastResult

d402 runtime
  owns retry count and backoff
  requests a new signature after nonce conflicts

Facilitator
  relays a supplied SignedTx once
```

The normal client execution path and the native facilitation path use the same signing and broadcasting capabilities. A facilitator never signs or repairs a transaction it receives.

## Public API decisions

The following abstractions are public:

```ts
D402Signer
D402TxBroadcaster
D402BroadcastResult
SignedTx
Facilitator
```

The following abstractions are removed:

```text
D402TxSender
txSender
createEthersTxSender
createViemTxSender
```

Do not create:

```text
D402Wallet
D402TxAdapter
isNonceConflict() on D402TxBroadcaster
```

`D402PaymentExecutor` remains the higher-level payment orchestration and extension point. It is not replaced by the signer or broadcaster.

## Broadcast result contract

### 1. Add `D402BroadcastResult`

File: `src/core/adapter.ts`

Keep the existing successful submission type:

```ts
export interface D402BroadcastedTx {
  readonly txHash: Hex32;
  waitForReceipt(): Promise<D402TxReceipt>;
}
```

Add:

```ts
export type D402BroadcastResult =
  | {
      ok: true;
      submission: D402BroadcastedTx;
    }
  | {
      ok: false;
      retryable: true;
      reason: "nonce-conflict";
      cause: unknown;
    }
  | {
      ok: false;
      retryable: false;
      reason: string;
      cause: unknown;
    };
```

Change the broadcaster interface to:

```ts
export interface D402TxBroadcaster {
  broadcastTx(
    tx: SignedTx,
  ): Promise<D402BroadcastResult>;
}
```

There is no `isNonceConflict` method on the public interface. Provider-specific classification occurs inside each adapter and is returned as data.

File: `src/core/index.ts`

Export:

```ts

```

alongside `D402BroadcastedTx`, `D402Signer`, and `D402TxBroadcaster`.

## Centralized retry behavior

### 5. Update the transaction runtime

File: `src/runtime/transaction.ts`

Keep:

```ts
export interface ExecutePreparedTransactionInput {
  signer: D402Signer;
  broadcaster: D402TxBroadcaster;
  tx: PreparedTx;
  onEvent?: D402EventHandler | undefined;
}
```

The function must emit `TransactionPreparedEvent` once per logical operation, then retry by signing again:

```ts
const NONCE_RETRY_LIMIT = 3;
const NONCE_RETRY_BASE_DELAY_MS = 300;

export async function executePreparedTransaction(
  input: ExecutePreparedTransactionInput,
): Promise<D402BroadcastedTx> {
  emitEvent(
    input.onEvent,
    new TransactionPreparedEvent(input.tx),
  );

  for (let attempt = 0; ; attempt += 1) {
    const signedTx =
      await input.signer.signTx(input.tx);

    const result =
      await input.broadcaster.broadcastTx(signedTx);

    if (result.ok) {
      return result.submission;
    }

    if (
      !result.retryable ||
      result.reason !== "nonce-conflict" ||
      attempt >= NONCE_RETRY_LIMIT
    ) {
      throw result.cause;
    }

    await delay(
      NONCE_RETRY_BASE_DELAY_MS * 2 ** attempt +
      Math.floor(
        Math.random() * NONCE_RETRY_BASE_DELAY_MS,
      ),
    );
  }
}

function delay(
  milliseconds: number,
): Promise<void> {
  return new Promise((resolve) => {
    setTimeout(resolve, milliseconds);
  });
}
```

The runtime is the only location that owns retry policy. It must never rebroadcast the same `SignedTx` after a nonce conflict.

Keep `createBroadcastQueue()` and `waitForSuccessfulReceipt()` unchanged unless compilation requires a type-only adjustment.

## Adapter changes

### 6. Remove adapter-owned retry logic

When migrating from `0.4.1`, remove from both adapters:

```text
NONCE_RETRY_LIMIT
NONCE_RETRY_BASE_DELAY_MS
sendWithNonceRetry()
sendQueue
adapter-side delay logic
```

The adapter may classify errors, but it must not retry, re-estimate, or re-sign.

### 7. Ethers signer

File: `adapters/ethers/src/signer.ts`

The signer must use `populateTransaction()` and `signTransaction()` only:

```ts
async signTx(
  transaction: PreparedTx,
): Promise<SignedTx> {
  const request =
    toEthersTransaction(transaction);

  const populated =
    await options.signer.populateTransaction({
      ...request,
      from: await options.signer.getAddress(),
    });

  return options.signer.signTransaction(
    populated,
  );
}
```

It must not call `signer.sendTransaction()`.

### 8. Ethers broadcaster

File: `adapters/ethers/src/tx-broadcaster.ts`

The broadcaster must:

1. call `provider.broadcastTransaction(signedTx)` once;
2. return `{ ok: true, submission }` on success;
3. map `NONCE_EXPIRED` to `{ ok: false, retryable: true, reason: "nonce-conflict" }`;
4. map other submission errors to `{ ok: false, retryable: false, ... }`;
5. never retry.

Use:

```ts
if (isError(error, "NONCE_EXPIRED")) {
  return {
    ok: false,
    retryable: true,
    reason: "nonce-conflict",
    cause: error,
  };
}

return {
  ok: false,
  retryable: false,
  reason: "broadcast-failed",
  cause: error,
};
```

Receipt waiting remains part of the successful `D402BroadcastedTx` submission and is not treated as a broadcast retry.

### 9. Viem signer

File: `adapters/viem/src/signer.ts`

The signer must use `prepareTransactionRequest()` and `signTransaction()` only:

```ts
async signTx(
  transaction: PreparedTx,
): Promise<SignedTx> {
  const account =
    getAccount(options.walletClient);

  const request =
    await options.walletClient
      .prepareTransactionRequest({
        ...toViemTransaction(
          transaction,
          account,
        ),
        account,
        chain: options.walletClient.chain,
      });

  return options.walletClient.signTransaction(
    request as never,
  );
}
```

It must not call `walletClient.sendTransaction()`.

### 10. Viem broadcaster

File: `adapters/viem/src/tx-broadcaster.ts`

The broadcaster must:

1. call `publicClient.sendRawTransaction()` once;
2. return `{ ok: true, submission }` on success;
3. map `NonceTooLowError` and `NonceTooHighError` to retryable nonce conflicts;
4. map all other submission errors to non-retryable failures;
5. never retry.

The private Viem provider classifier is allowed. It must only classify the error.

## Native facilitator

### 15. Update the facilitator

File: `src/server/facilitator.ts`

The facilitator returns the broadcast result directly:

```ts
import type {
  D402BroadcastResult,
  D402TxBroadcaster,
  SignedTx,
} from "../core/index.js";

export class Facilitator {
  constructor(
    private readonly broadcaster: D402TxBroadcaster,
  ) {}

  facilitate(
    signedTx: SignedTx,
  ): Promise<D402BroadcastResult> {
    return this.broadcaster.broadcastTx(signedTx);
  }
}
```

The facilitator does not retry because it has no `PreparedTx` or signer.

### 16. Export the facilitator

File: `src/server/index.ts`

Export:

```ts
export {
  Facilitator,
} from "./facilitator.js";
```

## Custom adapters

Custom adapters must implement the public result contract. They do not need to know d402 runtime internals.

Nonce conflict:

```ts
return {
  ok: false,
  retryable: true,
  reason: "nonce-conflict",
  cause: providerError,
};
```

Other failure:

```ts
return {
  ok: false,
  retryable: false,
  reason: "insufficient-funds",
  cause: providerError,
};
```

The result contract is public and type-checked. `cause` is for internal diagnostics and must not be serialized directly into an HTTP response.
